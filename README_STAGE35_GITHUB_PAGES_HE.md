# SUNSET STATE — פרסום גרסת שלב 35 ב־GitHub Pages

חבילת האתר היא **תיקייה סטטית מוכנה לפרסום**, לא אתר שכבר פורסם. היא מכילה את כל קובצי המשחק, נכסי התלת־ממד, `.nojekyll`, מרכז בדיקות (`STAGE35_FINAL_QA.html`) ו־GitHub Actions workflow (`.github/workflows/deploy-pages.yml`). אין להעלות רק את קובץ ה־ZIP כקובץ בתוך האתר — יש לחלץ את תוכנו לשורש המאגר.

## התקנה ב־GitHub

1. צור מאגר GitHub חדש או בחר מאגר ייעודי ל־SUNSET STATE. אל תפרסם במאגר שמיועד לפרויקט אחר. אם המאגר ציבורי, ודא שאתה רשאי לפרסם את כל הנכסים המצורפים.
2. חלץ את `SUNSET_STATE_STAGE35_GITHUB_PAGES_SITE.zip` לתיקיית העבודה המקומית של המאגר; שמור את מבנה `assets/`, `QA/`, `.github/`, `index.html` ו־`.nojekyll` כפי שהוא.
3. העלה את **כל הקבצים** בעזרת GitHub Desktop או `git add .`, `git commit -m "Release SUNSET STATE Stage 35"`, `git push origin main`.
4. במאגר פתח **Settings → Pages → Build and deployment → Source: GitHub Actions**. קובץ ה־workflow יפעל ב־push ל־`main` (או ב־Actions → Run workflow). אם ענף ברירת המחדל שונה, שנה את `main` בקובץ ה־workflow ובפקודת ה־push בהתאם.
5. חכה לסיום תהליך הפרסום ובדוק שהכתובת שקיבלת מציגה את `index.html` והנכסים נטענים בלי 404. עקוב אחר הכתובת שה־workflow יציג; **אין כאן כתובת ציבורית מאומתת מראש**.
6. פתח `STAGE35_FINAL_QA.html` באתר המפורסם, בצע את הבדיקות הידניות, וייצא דוח JSON. בדוק בשש סצנות ביצועי 1920×1080 ו־50FPS על GPU חומרתי.

## מגבלות ועקרונות

- חבילת המקור המלאה **אינה** מיועדת להעלאה כאתר ציבורי: היא מכילה קובצי QA, גיבויים וקוד מקור נוסף. פרסם רק את חבילת האתר.
- GitHub Pages מארח אתר סטטי בלבד. המנוע משתמש ב־WebGL2 וטעינת JavaScript בדפדפן, ללא שרת משחק.
- פתיחת `index.html` ישירות דרך מערכת הקבצים עלולה להיכשל עקב מדיניות `file://`. מומלץ HTTP/HTTPS.
- אם המשחק גדול מדי ל־GitHub Pages מבחינת מגבלות החשבון/האחסון שלך, שקול אירוח סטטי אחר והשתמש באותה חבילת אתר.
- **לא התבצע כאן push או פרסום ציבורי, וגם לא אימות GPU פיזי.**
